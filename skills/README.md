# Installed agent skills

These skills are tracked with the project so future Agent Mode sessions can load the same workflow.

| Skill | Local file | Upstream/provenance | Use |
|---|---|---|---|
| Karpathy guidelines | `karpathy-guidelines/SKILL.md` | [`multica-ai/andrej-karpathy-skills`](https://github.com/multica-ai/andrej-karpathy-skills), commit `2c606141936f1eeef17fa3043a72095b4765b9c2`; the upstream skill declares MIT. | Think before coding, keep changes simple and surgical, define acceptance evidence. |
| PUA workflow | `pua/SKILL.md` | Adapted from [`tanweai/pua`](https://github.com/tanweai/pua), portable `codex/pua/SKILL.md`, commit `e6e6cd237ad17750d179674bff52f8184abea8fd`; the upstream skill front matter declares MIT. | Persistent, evidence-first debugging, proactive regression review, and closed-loop verification. Rhetorical pressure is intentionally not imported. |
| Real-place builder | `real-place-builder/SKILL.md` | Project-authored from Huaxu's `grounded-scene`, `district-author`, Toronto/Niagara/CN Tower work and the visual-review workflow. | Mandatory environment-build and visual acceptance process. |
| Frame evidence | `frame-evidence/SKILL.md` (with `evals/evals.json`) | Project-authored, round 69k, from three instruments that could not report a miss (`verify-look`, `_view.mjs` v1-v2, `_ray.mjs` units) and the `.verify/_aim.mjs` implementation that replaced them. Built with the Agent Skills creator workflow (intent → draft → evals → baseline vs with-skill). Section 9 rewritten in round 79, when the same rectangle was quoted by two rounds as being on bare wall and on its model, and the paint in both readings was a colour heuristic; `.verify/verify-box.mjs` now tints one prop and presses its paint; section 9b was added in the same round's second pass, when the tint met a body CSS paints (no quad to tint) and a stale tint survived a repaint; section 9c was added in round 80, when `tools/bench.mjs` read a *frozen* `renderMs` (3,975 ms against a settled 3.4 ms) because the lane does not draw on a resting page and the average kept the shader-compile frame. | Arrival, aim, units, refusal: makes a frame and every number taken from it able to be wrong out loud — including *which pixels belong to the prop* (tint the prop, read its paint, press it), that a rectangle and its paint must come from the same frame, and that a published average must be fed real frames before it is quoted. |
| Scene system | `scene-system/SKILL.md` | Project-authored: the place-to-shipped pipeline as one system (owner's go-word → record → scene → gates). | Route a real-place build start to finish; owns the order the other skills run in. |
| Scene quality loop | `scene-quality-loop/SKILL.md` | Project-authored from the rendered-frame acceptance rounds (54-69). | Evidence-led visual acceptance after any scene, object, stop or camera change. |
| District author | `district-author/SKILL.md` | Project-authored from the Clifton Hill, Nakamise and Moji rounds. | Author a themed walkable district: intake questions, record shape, build rules, its own gate. |
| Grounded scene | `grounded-scene/SKILL.md` | Project-authored from the source-fidelity rounds. | Source-based spatial fidelity: real centimetres, what may and may not be compressed. |
| Lane prop | `lane-prop/SKILL.md` | Project-authored from the prop and light rounds (58-64). | Add or change one object, light, state or stop inside a district record (`SHAPE`/`OBJ_SIGN`). |
| Landmark space | `landmark-space/SKILL.md` | Project-authored from the CN Tower, drawbridge and station rounds. | Make one landmark object into its own walkable space with a real parent prop. |
| Japan place | `japan-place/SKILL.md` | Project-authored from the Tokyo (Nakamise, Hozomon, pagoda) and Moji rounds. | Japanese place vocabulary, real centimetres, night, prohibitions, the sakura-crossing study. |
| Street commons | `street-commons/SKILL.md` | Project-authored from the hub street rounds. | The hub street's layout system, regions, promenades and daylight. |
| Place intake | `place-intake/SKILL.md` | Project-authored from the owner's photograph-led rounds. | Turn supplied photographs into the record of a walkable room. |
| Walk input | `walk-input/SKILL.md` (with `evals/evals.json`) | Project-authored, round 71, from the 25/25 tap audit, the stall that lost its only route, and a turn paid in frames instead of the visitor's own milliseconds; extended in round 72 with the back gesture that left the room and the release that had no frame to land in. | How a press works in a walk room, how the head turns, and how a surface is left again: the bar, `detail === 0`, quiet-versus-dead, the 85 deg/s / 3 deg / 0.065 deg-per-px constants, the `overlayEntered`/`overlayLeft`/`popstate` exit contract, and the probes (`_popup-audit`, `_turnprobe`, `_backprobe`) and gates (`verify-overlay`, `verify-exit`) that measure them. |
| UX walkthrough | `ux-walkthrough/SKILL.md` (with `evals/evals.json`) | Project-authored, round 74, from the owner's four rulings on the same surface and from the Falls Incline, which announced a ride and moved nothing. The 10-heuristics review method follows [`tommyjepsen/awesome-ux-skills`](https://github.com/tommyjepsen/awesome-ux-skills) (`ux-heuristics-review`, `cognitive-load-conversion`); that repository has no licence file, so nothing from it is vendored here — the heuristics themselves are Jakob Nielsen's. | Walk the site as a visitor and judge a press by what it *changes on the screen*: the `press_verb` table, text only for `read`, the 47 %-drawer-vs-13 %-card measurement, and the pass (`_uxwalk`) plus gate (`verify-ux`) that find text-where-there-should-be-change and dead presses. |
| PR handoff | `pr-handoff/SKILL.md` | Project-authored, mandatory before every PR operation. Rewritten in round 82 by the owner's second ruling on the same subject (「我覺得都不需要」): the archive this skill had just created was deleted, and the skill now forbids a round log in any file. | The PR/TODO contract: `TODO.md` states the current open work and nothing about what earlier rounds did; a round's story is its commit message and PR body. |
| Dead ballast | `dead-ballast/SKILL.md` | Project-authored, round 76, from the attribute that was emitted, parsed and never applied (every "dusk" frame was noon), ten `.verify/` probes nothing invoked, and eight working gates missing from the checklist. Rewritten in round 77, when the owner ruled that a mention is not a user: 615 → 546 CSS selectors, a 259-line viewer no page could emit, a plan-view strip whose CSS round 72 had cut while its own commit message cited it as surviving. | Sweep out what does nothing — dead declarations, unwired attributes, unreferenced probes, gates nobody runs, doc lines for files that are gone, selectors no page matches, class tokens that style and hook nothing — decide dormant-vs-dead from the data, and prove the removal changed nothing a visitor sees. |
| Pure move split | `pure-move-split/SKILL.md` (with `scripts/split_by_ownership.py`, `scripts/spec-gen.py`) | Project-authored, round 78, from the owner asking whether React would make this easier and the answer being "no — two files are the problem", then an ownership-based split of the 7,484-line generator into a 715-line entry plus six modules, proven by 19 byte-identical pages. Written with the Agent Skills creator workflow. | Change a file's layout without changing a byte of its output: split by name ownership (never line number), prove it with an output checksum, fix the gates that go blind because they read one file as text, and know which file must **not** be split cosmetically. |
| Skill authoring | `skill-authoring/SKILL.md` | Project-authored, round 69l, from `skills/` holding fifteen skills while `skills/README.md` registered four. | When a lesson becomes a skill, how to write one, and keeping this register honest. |

The source repositories are references, not runtime dependencies. Use the local tracked files; do not add a package-manager install or a network dependency to this static site.
